# Store Vendor Availability controls local purchasing

Vendors and Vendor Items remain Organization-owned reusable purchasing definitions, and only the Organization vendor register may create them. Every Vendor has exactly one Store Vendor Availability per Store in the Organization. Creating a Vendor writes an **active** Availability for each current Store. Creating a Store writes an **inactive** Availability for each existing Vendor, plus Store Vendor Item Offerings seeded from each Vendor Item's default purchase price. Those two creation paths share an Organization-scoped transaction lock so a concurrent Vendor and Store creation cannot miss a pair. A Store Vendor Availability owns that Store's local purchasing switch (`active` or `inactive`); it cannot create a Store-private Vendor, and it is never deleted. Availability is status only. A Store Vendor Item Offering owns that Store's default purchase price and retains it while the Vendor is inactive at that Store. A Purchase Line still records the actual agreed price as history. Purchases accept only Vendors whose Availability is active at the selected Store. This supports store-specific purchasing without copying vendor identities, assigning selected Stores, or making module ownership a per-Organization toggle.
